## Project Type

**Plexis is a zero-dependency JavaScript/TypeScript library**, not a UI application.

This is important because the SOLID and TDD skill defaults assume a framework + components + design system + external services. In this project:

- There are **no components** (no React, Vue, Lit, or other UI framework).
- There are **no external services** (zero-dependency by design — no SDKs, no HTTP clients, no databases).
- There is **no router** (libraries are imported, not navigated).
- There is **no class utility** (`clsx` / `classnames` are UI concerns and not present).
- There is **no design system**.

The "unit" the SOLID skill should reason about in this project is an **exported module, class, or function from `src/core/` or `src/graph/`** — not a React component. Where the skill talks about "components", read it as "modules". Where it talks about "props", read it as "function parameters" or "constructor arguments". Where it talks about "DIP / external service boundaries", recognize that this library has none and the principle still applies internally (e.g., `Domain` should depend on the `Tracer` interface, not a concrete tracer implementation).

## Stack

**Language:** TypeScript (all `src/**/*.ts`). Authoritative interface definitions in `src/types.ts`; runtime implementations in `src/core/` and `src/graph/`.
**Build tool:** Rolldown — produces ESM (`dist/esm/`) and CJS (`dist/cjs/`) bundles from `src/index.js` via `rolldown.config.ts`. `tsc --emitDeclarationOnly` (via `tsconfig.types.json`) produces `dist/types/`. No other bundler.
**Test runner:** Vitest with `@vitest/coverage-v8`; configured in `vitest.config.ts`.
**Module formats:** ESM (`dist/esm/index.js`), CJS (`dist/cjs/index.cjs`), declarations (`dist/types/index.d.ts`). Dual-format via `"exports"` map in `package.json` (`"type": "module"`; `.cjs` extension for CJS).
**Runtime targets:** Node.js, browsers, serverless. Built-ins used: `crypto.randomUUID()` (Node 19+ / modern browsers).
**Workflow:** OpenSpec spec-driven change management in `openspec/changes/`.

**Explicitly absent (do not introduce):**
- No external runtime dependencies (zero-dependency guarantee — enforced at publish time).
- No UI framework (React, Vue, Svelte, Solid, Lit, etc.).
- No CSS-in-JS or class utilities (`clsx`, `classnames`, `tailwind-merge`, etc.).
- No database SDKs or HTTP clients.

**Module purpose per layer:**

- `src/core/*` — one responsibility per file. Each module exports either a class (with its factory) or a focused utility. No cross-imports between unrelated core modules (e.g., `pipeline.js` may import `tracer.js`, `errors.js`, `context.js`, `helpers.js` — but `tracer.js` must not import `pipeline.js`).
- `src/graph/*` — pure functions over `GraphDescriptor`. No runtime side effects, no imports from `src/core/` (graph is consumed by core, not the other way around).
- `src/types.ts` — types only, no runtime code.
- `src/index.js` — re-exports only, no logic.

## Test Conventions

- Test runner: **Vitest** with `@vitest/coverage-v8`; config in `vitest.config.ts`.
- Test location: `tests/**/*.test.ts` — separate from `src/`, not co-located.
- Test environment: `node` (no DOM; this is a universal library and DOM-free tests prove portability).
- Naming pattern: `describe()` / `it()` blocks; one file per module under test (`tests/domain.test.ts` covers `src/core/domain.ts`).
- Coverage: every scenario in `openspec/changes/bootstrap-plexis-core/specs/**/spec.md` must map to at least one passing test (enforced by task 11.1).
- Spec→test traceability: comments at the top of each describe block reference the spec requirement they cover.

**Mock/spy boundaries:**

- No external SDKs to mock — this library has none.
- For internal dependencies (e.g., asserting that `Domain` calls `Tracer.record` with the right shape), use the test runner's spy API (`jest.fn()` / `vi.fn()`).
- Time-sensitive tests inject a `clock` via `TracerOptions.clock` rather than mocking `Date.now()` globally.
- Id-sensitive tests inject `idFactory` via `TracerOptions.idFactory` for determinism.

**Run commands:**

- `npm test` — single run (`vitest run`)
- `npm run test:watch` — watch mode (`vitest`)
- `npm run typecheck` — `tsc --noEmit`
- Single-file run: `npx vitest run tests/path/to/file.test.ts`

**Assertion / spy / stub library:**

- `expect(...).toEqual(...)` style (Vitest built-in).
- Spies via `vi.fn()` / `vi.spyOn(...)`; module mocking via `vi.mock(...)` available but **prefer dependency injection** (see DIP boundary below).

**Bootstrap / setup helpers:**

- **Not applicable.** No DOM, no app init, no router. Tests construct the units under test directly (e.g., `const tracer = createTracer(); const domain = defineDomain('order', () => {...});`).
- Reusable test factories (e.g., a deterministic `Tracer` with injected `clock` and `idFactory`, an in-memory `merge` strategy for deep-merge tests) MAY live in `tests/_support/` once tests start being written. Do not co-locate fixtures inside spec files.

**Coverage posture:**

- **No numeric coverage threshold.** Coverage is measured but not enforced as a number — the binding requirement is that every scenario in `openspec/changes/bootstrap-plexis-core/specs/**/spec.md` maps to at least one passing test (task 11.1).
- Coverage report scope: `src/core/**/*.ts` and `src/graph/**/*.ts` (exclude `src/types.ts` and `src/index.ts` since they are types-only or re-exports-only).

**TDD-specific conventions:**

- **One failing test at a time.** Add the rest of the upcoming cases to a `// @TODO` list at the top of the spec file, keyed by the spec scenario name they cover (e.g., `// @TODO follow() — Successful event follows the matching edge`).
- **Spec→test mapping is the source of truth.** Each `describe` block SHALL include a comment referencing the requirement and scenario from the OpenSpec spec it covers (e.g., `// covers: specs/domain/spec.md → Requirement: State transitions via follow → Scenario: Successful event follows the matching edge`). This makes the task 11.1 audit mechanical.
- **Bootstrapping pattern for not-yet-implemented modules:** create the stub (`export function defineDomain(...) { throw new Error('not implemented'); }`) so the spec file compiles and runs red. Then make it green. Never write more than one red test before greening it.
- **Spy cleanup:** `restoreMocks: true` is set in `vitest.config.ts` — mocks are auto-restored between tests; no manual `afterEach` cleanup needed.

## Notes

### Module model (replaces "Component model")

The unit the SOLID skill should reason about in Plexis is **the exported function, class, or factory from a `src/core/` or `src/graph/` module**.

- **Authoring API surface** — `defineDomain`, `definePipeline`, `createTracer` factories plus `when`, `enter`, `exit`, `on`, `node`, `action`, `fork`, `terminal` registration helpers. Each is a single-purpose exported function.
- **Class constructors** — `Domain`, `Pipeline`, `Tracer`, `PlexisError`. Each satisfies the interface declared in `src/types.ts` and routes through the same internal builder (`buildDomain`, `buildPipeline`) as its factory.
- **Pure utility modules** — `src/graph/descriptor.js`, `src/graph/paths.js`, `src/graph/inspection.js`, `src/core/context.js`. No state, no side effects, accept input and return output.
- **Interface contract** — `src/types.ts` declares `Domain<TContext, TEdges>`, `Pipeline<TContext>`, `Tracer`, plus all `*Def` / `*Config` shapes. **Class instances must satisfy these interfaces.** New methods or properties added to a class without updating `src/types.ts` are a SOLID violation (LSP — substitutability is broken if the published type doesn't reflect the runtime shape).

### Class utility

**Not applicable.** This library does not produce any HTML or CSS. The skill's "class utility" rules can be skipped.

### External data boundaries (DIP)

**No external services exist in this library.** The DIP principle still applies internally:

- Plexis primitives depend on the `Tracer` **interface** (from `src/types.ts`), not on the concrete `Tracer` class. Anywhere a Tracer is consumed (Domain, Pipeline edge actions, etc.), the consumer SHALL accept an object satisfying the `Tracer` interface, not import the concrete class. This allows tests to pass in a fake Tracer.
- The `merge(prev, patch, metadata)` function is injected via options — it's a strategy abstraction. Code that hard-codes shallow-merge inside `Domain.follow` (instead of routing through `applyMerge`) violates DIP.
- User-supplied `idFactory` and `clock` in `TracerOptions` are injected abstractions for ID generation and time — Plexis must use them through the interface, never call `crypto.randomUUID()` or `Date.now()` directly inside business logic.

**DIP enforcement boundary:** if a consumer would otherwise need to monkey-patch global APIs (`Date.now`, `crypto.randomUUID`, `console`) to test code, that's a DIP violation — surface the dependency as an injectable option instead.

### Project-specific exceptions and reminders

- **`src/types.ts` is authoritative.** Any drift between a class's public surface and the corresponding interface in `src/types.ts` is treated as a violation. Update the type, not just the implementation.
- **Setup-function helpers (`when`, `enter`, `exit`, `on`, `node`, `action`, `fork`, `terminal`) use a nested builder-scope stack.** This is intentional — the spec mandates it. Do NOT flag the module-level scope stack as a SOLID violation; it's the documented mechanism for the composable authoring API.
- **`PlexisError` static factory helpers** (`PlexisError.unknownEvent(...)` etc.) are intentional — they encapsulate the construction of typed errors. Do NOT flag this pattern as a god class; each factory has one responsibility (one error code).
- **OpenSpec artifacts in `openspec/changes/**` are NOT code.** They are project planning documents and are exempt from all SOLID/code-style rules.
- **`.specs/plexis/` is a read-only reference implementation** of the older options-based API. It is not the target and its code style is not authoritative — do not propagate patterns from it into `src/`.

### TypeScript posture

- `strict: true` in `src/tsconfig.json` — enforced; never relax per-file.
- No `any` — use `unknown` with type guards or proper generics. The `src/types.ts` file already follows this; preserve it.
- No `as unknown as T` casts.
- Use `satisfies` to constrain config objects to interfaces without widening.
- Public exports from `src/index.js` must match a corresponding `export` in `src/types.ts` (or be re-typed via JSDoc in `src/types.js`).

### What the SOLID skill enforces in this project

Reading the skill against this config:

| Principle | What it means here |
|---|---|
| **SRP** | One file per primitive (`domain.js`, `pipeline.js`, `tracer.js`, `errors.js`, `context.js`, `helpers.js`). One reason to change per file. Functions named `handleXAndY` still split. Modules ≤ ~300 lines (libraries can be denser than UI components; ~150 is too tight). |
| **OCP** | Extend via options/strategy injection (custom `merge`, custom `idFactory`, custom `clock`, custom `errorPolicy`) — not by editing `Domain.follow`. New error codes added via static factories on `PlexisError`, not by patching every throw site. |
| **LSP** | Class instances must satisfy `src/types.ts` interfaces exactly. `new Domain(...)` and `defineDomain(...)` must produce instances that behave identically — covered by parity tests. |
| **ISP** | `*Def` / `*Config` interfaces should be focused. Don't expand `OnDef` with fields only some flows use — add a separate concern. Don't pass a god `Options` bag where a focused one would do. |
| **DIP** | Inject `Tracer`, `merge`, `idFactory`, `clock` rather than calling them directly. Tests substitute fakes through the same injection points. |
