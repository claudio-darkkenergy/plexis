# Install: solid-principles skill

Run this once when adding the solid-principles skill to a new project. Follow each step in order.

---

## Step 1 — Check for existing skill-config.md

Check whether `.claude/skills/skill-config.md` exists.

**If it already exists:**

- Read the file.
- Proceed to Step 2 to verify and fill in any missing values.
- Do not overwrite values already present — only append missing ones.
- After Step 2, report what was added vs. what was already present and skipped.

**If it does not exist:**

- Proceed to Step 2 to auto-discover conventions, then create the file from scratch using the structure below.

---

## Step 2 — Auto-discover project conventions

Read the following files and derive the config values listed under each:

**`package.json`** (root and any relevant workspace packages):

- All dependency names and exact versions relevant to: framework, design system, component utilities, class utilities, services/APIs, test runner, assertion library, spy/stub library, TypeScript, build tools.
- Note any tools that are explicitly **absent** (e.g., no Jest, no Drizzle, no Tailwind) — these are as important as what is present.

**`tsconfig.json`** (root, plus any shared tsconfig files referenced):

- `strict`, `noUncheckedIndexedAccess`, `target`, `module`, `moduleResolution`
- Path aliases (`paths`) and their resolved directories

**Test runner config** (e.g., `jest.config.ts`, `vitest.config.ts`, `web-test-runner.config.mjs`, or equivalent):

- Test environment (`testEnvironment`, `puppeteer`, browser vs. Node)
- Transformer / plugin
- tsconfig used for tests
- `moduleNameMapper` / path alias overrides
- Global setup files
- Coverage config (include/exclude patterns)

**Project folder structure** (read `ls` of key directories):

- Where components live (tag wrappers, design-system elements, app components)
- Where services and API handlers live
- Where service-layer abstractions (interfaces) live or should live
- Where utility libraries live
- Where types are defined
- Where test support files (fixtures, mocks, bootstrap helpers) live

**An existing test file** (if any — find the first `.spec.ts` or `.test.ts`):

- Confirm naming convention: `describe` / `it` or `test` style
- Confirm placement: co-located, `__tests__/`, `tests/unit/`, etc.
- Confirm import style for assertion and mock libraries

**Router config** (e.g., `next.config.ts`, or the project's routing module):

- App Router vs. Pages Router vs. custom routing
- Route entry point file locations

**`CLAUDE.md`** (if it exists):

- Any already-documented conventions that should be reflected in skill-config.md

After completing standard discovery, also discover and append a `## Component Model` section to skill-config.md by reading the project source to identify:

- Layer names and their responsibilities (e.g. app, components, services, utilities — whatever folder structure exists)
- Component pattern in use (React functional components, class components, or other)
- HOF or modifier pattern if present
- Reactive primitive pattern if present

If `## Component Model` already exists in skill-config.md, check for missing entries and append only what is absent.

---

## Step 3 — Write or update skill-config.md

Using the values discovered in Step 2, write (or update) `.claude/skills/skill-config.md` with this structure:

```markdown
# Skill Config

_Shared configuration for all skills in this project.
Generated by install.md — update this file when project conventions change._

---

## Stack

[All relevant tool names and versions from package.json]
[Explicitly note absent tools: "No X, Y, Z"]

---

## Folder Conventions

[All layer folders and their purposes — components, services, utilities, types, tests]
[Prescribed but not-yet-created folders (e.g., service interface location)]

---

## Test Conventions

[Test runner, environment, spec location, support paths, naming pattern]
[Run commands for CI, watch, and debug modes]
[Mock/spy API — which library and which functions to use]
[Coverage config]

---

## Router Type

[App Router | Pages Router | custom — with entry point paths]

---

## Notes

[Component model — what the component unit is for this framework]
[Class utility — which one is in use; what is prohibited]
[External data boundaries — which external services exist; where DIP interfaces go]
[Any framework-internal APIs that must NOT be flagged as DIP violations]
[Any project-specific exceptions to standard SOLID rules]
```

If updating an existing file: append new sections or values at the end of each relevant section. Never overwrite existing values.

---

## Step 4 — Add Skill Config Rule to CLAUDE.md

Check whether `## Skill Config Rule` already exists in `CLAUDE.md`.

**If it already exists:** skip — do not duplicate.

**If it does not exist:** append the following to `CLAUDE.md`:

```markdown
## Skill Config Rule

If any change affects folder structure, import aliases, dependencies,
test configuration, or architectural conventions, update
`.claude/skills/skill-config.md` as part of that same task. This file
is the source of truth for all skill behavior in this project.
```

---

## Step 5 — Confirm to the user

Report the following:

1. **Discovered from the project:**
    - Framework, test runner, and build tool identified
    - Folder structure mapped (list the key folders found)
    - Test convention confirmed (naming pattern, spec location, environment)
    - Router type identified

2. **Written or updated in skill-config.md:**
    - List each section that was written or updated
    - List any values that were already present and skipped

3. **CLAUDE.md:**
    - Whether `## Skill Config Rule` was added or already present and skipped

4. **Ambiguities requiring manual resolution:**
    - List any folder patterns where two competing conventions exist and Claude cannot determine which is canonical
    - List any missing config files (e.g., no jest.config.ts found, no tsconfig.json at root)

5. **Reminder:**
    - `install.md` does not need to be run again unless the project is being reconfigured from scratch.
    - To add the solid-audit skill, run `.claude/skills/solid-audit/install.md`.
    - To add the tdd-workflow skill, run `.claude/skills/tdd-workflow/install.md`.
