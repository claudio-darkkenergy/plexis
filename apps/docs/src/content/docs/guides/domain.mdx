This guide walks through the most common domain patterns: defining states and flows, guarding transitions, running lifecycle hooks, subscribing to changes, and persisting flow state with snapshots. For complete signatures and field tables, see the [Definition Functions](/reference/definition-functions/), [Registration Helpers](/reference/registration-helpers/), and [Domain Instance](/reference/domain/) reference pages.

A **Domain** models durable business state that persists across time. It has named states, flows (event-driven transitions), lifecycle hooks, and can invoke pipelines on flows.

## Defining a Domain

Use `defineDomain()` to create a domain. The setup function runs synchronously and registers states using the `when()` helper.

```typescript
import { defineDomain, when, on, terminal } from '@tde.io/plexis';

type OrderContext = { orderId: string | null };

const order = defineDomain<OrderContext>('order', () => {
  when('pending', () => {
    on('submit', { target: 'processing' });
  });
  when('processing', () => {
    on('fulfill', { target: 'fulfilled' });
  });
  when('fulfilled', terminal());

  return {
    context: { orderId: null },
    initial: 'pending',
  } as const;
});
```

The `as const` annotation on the return value enables TypeScript to narrow the allowed event names in `follow()` and `can()`.

## States

Register states with `when(id, fn | terminal())`. The setup function receives no arguments; it calls scoped helpers to configure the state:

| Helper | Description |
| --- | --- |
| `on(event, def)` | Register a named flow out of this state |
| `enter(fn)` | Runs when the domain enters this state |
| `exit(fn)` | Runs when the domain exits this state |

Pass `terminal()` as the second argument to register a terminal state with no further behavior.

## Flows

Register a flow on a state using `on(event, { target, guard?, action?, pipeline? })` inside a `when` setup:

```typescript
when('pending', () => {
  on('submit', {
    target: 'processing',
    guard: (ctx) => ctx.orderId !== null,
    action: async (ctx) => ({ submitted: true }),
  });
});
```

The `guard` receives the current context and returns a boolean. If it returns `false`, the transition is blocked — no hooks or actions run.

The `action` receives the current context and an `OnActionInput` (event name, payload, trace ID) and returns a context patch merged as `{ ...prev, ...patch }`.

## Lifecycle Hooks

`enter` and `exit` run when the domain enters or leaves a state. Call them inside the `when` setup function. Both receive the current context and a `StateHookInput` (event name, payload, trace ID). Both can return context patches.

```typescript
when('processing', () => {
  enter(async (ctx, { event }) => {
    console.log(`Entered processing via ${event}`);
    return { enteredAt: Date.now() };
  });
  exit(async (ctx) => {
    console.log('Leaving processing');
  });
  on('fulfill', { target: 'fulfilled' });
});
```

**Execution order on `follow(event, payload)`:**

1. Guard check — blocks if `false`; no side effects run
2. `exit` for the current state
3. Flow action
4. Flow pipeline
5. State transitions to target
6. `enter` for the target state
7. State entry pipeline
8. History recorded, subscribers notified

## Advancing State with `follow()`

Call `domain.follow(event, payload?)` to trigger a transition.

```typescript
const result = await order.follow('submit');

console.log(result.status);  // 'followed'
console.log(result.from);    // 'pending'
console.log(result.to);      // 'processing'
console.log(result.context); // updated context
```

See [DomainFollowResult](/reference/types#domainfollowresult) for the complete field reference.

## Checking Whether a Transition Is Allowed

Use `domain.can(event)` to test whether an event can be followed from the current state without triggering any side effects:

```typescript
const canSubmit = await order.can('submit');
```

## Subscriptions and History

Subscribe to state changes:

```typescript
const unsub = order.subscribe((snapshot) => {
  console.log(snapshot.state, snapshot.context);
});

// Later:
unsub();
```

Retrieve the transition history:

```typescript
const entries = order.history();
// Each entry: { from, to, event, payload?, context, timestamp, traceId }
```

## Snapshots

`snapshot()` captures the current state and context at a point in time. `restore()` winds the domain back to that captured point — useful for undo/redo, testing, and persisting flow state.

```typescript
// Persist wizard flow to localStorage so the user can resume later
const snap = order.snapshot();
localStorage.setItem('order-flow', JSON.stringify(snap));

// On page reload — restore exactly where the user left off
const saved = localStorage.getItem('order-flow');
if (saved) order.restore(JSON.parse(saved));
```

In tests, snapshots let you jump the domain to any starting state without replaying events:

```typescript
const processingState = {
  state: 'processing',
  context: { orderId: '123' },
  historyLength: 1,
};
order.restore(processingState);

// Now test transitions from 'processing' directly
const result = await order.follow('fulfill');
```

## Strict Mode

Pass `strict: true` in the setup return to throw a `PlexisError` when an unknown event is sent (instead of returning `status: 'ignored'`):

```typescript
return { context: {}, initial: 'pending', strict: true } as const;
```

## TypeScript Flow Inference

Using `as const` on the setup return value lets TypeScript infer the exact set of valid event names:

```typescript
const order = defineDomain('order', () => {
  when('pending', () => { on('submit', { target: 'processing' }); });
  when('processing', terminal());
  return { context: {}, initial: 'pending' } as const;
});

await order.follow('submit');  // ✓ OK
await order.follow('cancel');  // ✗ TypeScript error
```
